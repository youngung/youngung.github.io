1. 왜 분석 코드의 변경을 기록할까?

앞 강의에서 작성한 그래프의 축 이름과 격자 표시를 바꿨다고 하자. 한 달 뒤 같은 그림을 다시 그리려면 어느 파일을 고쳤고 어떤 설정을 사용했는지 알아야 한다. Git은 파일의 변경을 기록하는 버전 관리 도구다. 의미 있는 변경마다 기록을 남기면 이전 코드와 현재 코드의 차이를 줄 단위로 살펴볼 수 있다.

저장소(repository)는 프로젝트 파일과 그 변경 이력을 관리하는 단위다. 내 컴퓨터의 저장소를 로컬 저장소(local repository)라고 한다. GitHub는 Git 저장소를 온라인에 두고 공유하거나 변경을 검토할 수 있는 서비스다. GitHub에 연결한 저장소는 이 실습에서 원격 저장소(remote repository)가 된다. Git의 로컬 작업은 GitHub 계정 없이도 할 수 있다.

이번 실습에서는 작은 Matplotlib 프로젝트의 첫 버전을 기록하고 GitHub로 보낸다. 이어서 별도의 작업 줄기에서 그래프를 수정하고 GitHub에서 변경 내용을 검토한다.

2. Git 설치와 GitHub 계정 만들기

Git 설치 확인

VS Code의 터미널을 열어 다음 명령을 실행한다. Windows에서는 Git for Windows에 포함된 Git Bash를 사용해도 된다. 코드 블록에서 bash는 명령을 입력할 셸의 종류를 뜻한다.

git --version

git version으로 시작하는 줄이 나오면 설치되어 있다. 명령을 찾을 수 없으면 운영체제에 맞는 Git을 설치하고 터미널을 다시 연다. Windows는 Git for Windows, macOS는 xcode-select --install을 통한 Command Line Tools, Linux는 배포판의 패키지 관리자를 사용할 수 있다. Git 설치 안내

GitHub 가입과 이메일 설정

  1. GitHub 가입 화면에서 개인 계정을 만든다. 사용자 이름(username)은 프로필과 저장소 주소에 쓰인다. 가입 화면
  2. 가입에 사용한 이메일을 확인하고 받은 편지함에서 인증을 완료한다. 계정 설정에서 2단계 인증(2FA)을 구성하고 복구 코드는 개인 기기에 보관한다. GitHub 계정 시작 안내
  3. 커밋에는 작성자 이름과 이메일이 기록된다. 개인 이메일 공개를 피하려면 GitHub의 Settings → Emails에서 계정에 부여된 noreply 주소를 확인해 아래 이메일 자리에 넣는다. 커밋 이메일 설정 
git config --global user.name "내 이름"
git config --global user.email "내 커밋 이메일"
git config --get user.name
git config --get user.email

따옴표 안의 값은 자신의 이름과 이메일로 바꾼다. --global은 이 컴퓨터의 현재 사용자 계정에 기본값을 저장한다. 수업용 컴퓨터에서 프로젝트별로 설정하려면 아래의 git init을 먼저 실행한 뒤 해당 폴더에서 --global 대신 --local을 사용한다. 이 이름과 이메일은 작성자 정보다. GitHub 로그인은 원격 저장소 연결 단계에서 별도로 진행한다.

VS Code에서 Git을 확인하고 GitHub 확장 설치하기

수업에서는 VS Code의 Source Control(소스 제어) 패널에서 변경 사항을 확인하고 커밋한다. 이 패널은 VS Code에 내장되어 있으며, 앞에서 설치한 Git을 사용한다. GitHub Pull Requests 확장은 VS Code에서 Pull Request(PR)를 만들고 검토할 때 사용한다.

  1. 왼쪽 활동 표시줄에서 Extensions(확장)를 연다. 단축키는 Windows·Linux에서 Ctrl+Shift+X, macOS에서 Cmd+Shift+X다.
  2. 검색창에 @id:GitHub.vscode-pull-request-github를 입력한다. 게시자가 GitHub인 GitHub Pull Requests 확장을 선택하고 Install(설치)을 누른다.
  3. 확장 상세 화면에 Uninstall(제거) 버튼이 나타나면 설치된 상태다. 활동 표시줄에서 GitHub 보기를 열고 Sign In을 선택한다. 브라우저에서 방금 만든 계정으로 로그인하고, 승인 화면을 거쳐 VS Code로 돌아온다.
  4. Source Control 아이콘도 열어 본다. 실습 저장소를 열기 전에는 커밋할 파일이 표시되지 않아도 된다. Git을 찾을 수 없다는 안내가 나오면 VS Code를 완전히 닫았다가 다시 열고, 통합 터미널에서 git --version을 다시 확인한다.

3. 실습 1 — 그래프의 첫 버전 기록하기

터미널에서 수업 파일을 저장하는 폴더로 이동한다. 그곳에 실습 폴더를 만들고 새 저장소를 시작한다. -b main은 기본 작업 줄기의 이름을 main으로 정하는 옵션이다.

mkdir data-mse-plot
cd data-mse-plot
git init -b main

편집기에서 이 폴더를 열고 plot_data.py를 만든다. 가상의 측정 데이터를 사용한 예시다.

import matplotlib.pyplot as plt

time_s = [0, 1, 2, 3, 4]
signal_mv = [0.2, 1.0, 2.1, 2.9, 4.2]

fig, ax = plt.subplots()
ax.scatter(time_s, signal_mv)
ax.set_xlabel("Time (s)")
ax.set_ylabel("Signal (mV)")
fig.savefig("plot.png", dpi=150)

같은 폴더에 README.md를 만들고 아래 내용을 넣는다. README는 프로젝트의 목적과 실행 방법을 설명하는 문서이며, GitHub 저장소 첫 화면에서도 읽을 수 있다.

# Data MSE Plot

가상의 시간–신호 측정값을 산점도로 표시한다.

Matplotlib이 설치된 Python 환경에서 `python plot_data.py`를 실행하면 plot.png가 생성된다.

이 실습에서는 그림을 코드로 다시 만들 수 있으므로 생성한 plot.png는 버전 관리에서 제외한다. 저장소의 최상위 폴더에 .gitignore 파일을 만들고 다음 두 줄을 넣는다. .gitignore는 아직 추적하지 않는 파일 가운데 Git이 보통 무시할 경로를 지정한다.

/plot.png
__pycache__/

VS Code에서 첫 커밋 만들기

File → Open Folder에서 data-mse-plot 폴더를 열고, 통합 터미널에서 python plot_data.py를 실행한다. 환경에 따라 python3 또는 py를 사용할 수 있다. 이어서 Source Control에서 다음 순서로 작업한다.

  1. Changes 아래의 plot_data.py를 클릭해 커밋할 내용을 확인한다. 생성한 plot.png는 .gitignore 규칙 때문에 목록에 나타나지 않는다.
  2. README.md, plot_data.py, .gitignore 각각의 오른쪽에서 +를 눌러 Staged Changes로 옮긴다. 이 동작이 git add에 해당한다.
  3. Staged Changes에 세 파일이 있는지 확인한다. 메시지 입력란에 Add measurement scatter plot을 적고 Commit을 누른다. 작업을 마치면 Source Control Graph 또는 통합 터미널의 git log --oneline에서 첫 커밋을 확인한다.

VS Code의 스테이징과 커밋 안내

같은 작업을 터미널에서 수행하기

터미널만으로 첫 커밋을 만드는 경우 아래 명령을 실행한다. VS Code에서 커밋을 마쳤다면 마지막 두 확인 명령만 실행해도 된다.

git status --short
git add README.md plot_data.py .gitignore
git diff --staged
git commit -m "Add measurement scatter plot"
git status --short
git log --oneline

커밋 전에는 git status --short에서 새 파일 세 개 앞에 ??가 보이고 plot.png는 목록에서 빠진다. 커밋 직후에는 git status --short의 출력이 비고, git log --oneline에는 커밋을 식별하는 짧은 ID와 메시지가 한 줄로 나타난다.

위치 이 실습에서 하는 일
작업 폴더(working tree) 편집기에서 실제 파일을 만들고 수정한다.
스테이징 영역(staging area) git add로 다음 커밋에 포함할 파일의 현재 내용을 골라 담는다.
로컬 저장소(local repository) git commit으로 스테이징 영역의 내용을 설명과 함께 기록한다.
원격 저장소(remote repository) git push로 로컬 브랜치의 커밋을 GitHub에 보낸다.

커밋(commit)은 그 시점에 선택한 프로젝트 상태를 남긴 기록이다. 파일을 스테이징한 뒤 편집하면 새 편집 내용은 작업 폴더에 남는다. git diff는 스테이징 이후 작업 폴더에 생긴 변경을, git diff --staged는 마지막 커밋과 비교해 다음 커밋에 들어갈 변경을 보여 준다.

4. 실습 2 — GitHub에 첫 버전 올리기

VS Code에서 비공개 저장소로 게시하기

아직 GitHub에 data-mse-plot 저장소를 만들지 않았다면, VS Code에서 로컬 저장소를 바로 게시할 수 있다.

  1. 명령 팔레트(Windows·Linux Ctrl+Shift+P, macOS Cmd+Shift+P)에서 Publish to GitHub를 실행한다.
  2. 로그인 요청이 나오면 브라우저에서 인증한다. 저장소 이름을 data-mse-plot으로 입력하고 Private을 선택한다.
  3. 게시가 끝나면 GitHub에서 파일 목록과 첫 커밋을 확인한다. VS Code가 원격 저장소를 연결하고 첫 커밋을 전송했는지는 통합 터미널에서 git remote -v와 git status -sb로도 확인할 수 있다.

VS Code의 저장소 게시 안내

GitHub 웹에서 저장소를 만들고 터미널로 푸시하기

터미널로 게시하려면 다음 절차를 사용한다. GitHub 웹에서 실습용 빈 저장소를 미리 만들었다면 저장소 생성 단계를 건너뛰고 3단계부터 진행한다.

  1. GitHub에 로그인해 New repository를 선택한다. 이름은 data-mse-plot, 공개 범위는 실습용으로 Private을 선택한다. 공개 저장소(Public)는 누구나 볼 수 있고 비공개 저장소는 권한을 가진 사용자가 볼 수 있다.
  2. 로컬에서 첫 커밋을 이미 만들었으므로 GitHub에서는 README, .gitignore, 라이선스 추가 옵션을 선택하지 않고 빈 저장소를 만든다.
  3. GitHub CLI를 별도로 설치한다. 터미널에서 gh auth login을 실행해 GitHub.com, HTTPS, 브라우저 로그인을 선택한다. 브라우저에서 로그인을 마친 뒤 아래 명령으로 로그인 상태를 확인하고 Git의 인증을 설정한다. GitHub CLI 인증 안내
  4. 아래 URL의 USERNAME을 자신의 GitHub 사용자 이름으로 바꿔 실행한다. GitHub 저장소 화면에서 HTTPS 주소를 복사해 넣어도 된다.
gh auth status
gh auth setup-git
git remote add origin https://github.com/USERNAME/data-mse-plot.git
git remote -v
git push -u origin main

origin은 이 원격 저장소에 붙인 이름이다. -u는 로컬의 main을 원격의 main과 연결해 이후에 이 브랜치에서 git push와 git pull의 대상 지정을 생략할 수 있게 한다. GitHub 저장소 페이지를 새로고침하고 파일 목록과 커밋 메시지를 확인한다.

실제 분석 자료를 올리기 전에는 git diff --staged로 포함될 내용을 확인한다. 비밀번호, 토큰, 개인정보, 공개 권한이 없는 실험 데이터는 커밋 대상에서 제외한다. 이미 커밋한 파일을 이후 버전에서 삭제해도 앞선 커밋에는 내용이 남을 수 있다.

5. 실습 3 — 브랜치에서 수정하고 Pull Request로 검토하기

VS Code에서 브랜치와 Pull Request 만들기

  1. VS Code 창 아래의 현재 브랜치 이름 main을 클릭하고 Create new branch…를 선택한다. 이름은 add-grid로 정하고, 상태 표시줄에 새 브랜치 이름이 보이는지 확인한다.
  2. plot_data.py에서 fig.savefig(...) 바로 위에 ax.grid(True, alpha=0.3)을 넣고 저장한다. 통합 터미널에서 스크립트를 실행해 격자가 추가됐는지 확인한다.
  3. Source Control에서 변경된 한 줄을 확인하고 +로 스테이징한다. Add grid to measurement plot이라는 메시지로 커밋한 뒤 Publish Branch를 눌러 add-grid를 GitHub에 올린다.
  4. 명령 팔레트에서 GitHub Pull Requests: Create Pull Request를 찾아 실행한다. 변경을 받을 저장소와 브랜치(base)가 자신의 data-mse-plot의 main인지, 변경을 보낼 브랜치(compare)가 add-grid인지 확인한다.
  5. 제목과 변경 내용을 입력하고 Create를 누른다. 열린 PR에서 수정된 파일을 열어 격자 코드 한 줄을 확인한다. GitHub 웹 또는 확장에서 PR을 병합한 뒤, VS Code에서 main으로 전환하고 Source Control → … → Pull로 변경을 가져온다.

터미널과 GitHub 웹에서 같은 작업 수행하기

브랜치(branch)는 커밋이 이어지는 작업 줄기다. 현재의 main에서 add-grid 브랜치를 만들면 첫 그래프 버전을 바탕으로 격자 추가를 시험할 수 있다.

git switch -c add-grid

plot_data.py에서 fig.savefig(...) 바로 위에 ax.grid(True, alpha=0.3)을 추가한다. alpha는 투명도를 조절하는 값이다. 다시 실행해 plot.png에 격자가 나타나는지 확인하고, 코드 변경을 기록한다.

python plot_data.py
git diff
git add plot_data.py
git diff --staged
git commit -m "Add grid to measurement plot"
git push -u origin add-grid
  1. GitHub에서 Pull Request를 열어 비교 대상을 main(base), 변경을 가져올 브랜치를 add-grid(compare)로 지정한다. Pull Request는 변경을 합치기 전에 차이를 검토하고 의견을 남기는 요청이다.
  2. Files changed에서 추가된 한 줄을 확인한다. 설명에 무엇을 바꿨고 그림에서 어떻게 확인했는지 적는다.
  3. 검토를 마치면 GitHub에서 Merge pull request로 변경을 main에 합친다. 팀 실습에서는 합치기 전에 팀원에게 검토를 요청할 수 있다.
  4. 터미널에서 로컬의 main으로 돌아와 원격의 변경을 받아온다. --ff-only는 로컬 브랜치가 원격 이력을 그대로 따라갈 수 있을 때만 업데이트하게 한다.
git switch main
git pull --ff-only
git log --oneline -5

GitHub Flow 안내

아래 그림은 GitHub에서 Create a merge commit 방식으로 합친 경우다. 원은 커밋이고, 화살표는 이전 커밋에서 다음 커밋으로 이어지는 경로를 나타낸다. main의 첫 커밋에서 갈라져 나온 격자 추가 작업과 기존 main 이력이 병합 커밋에서 만난다.

다른 컴퓨터에서 처음 이어서 작업할 때는 실습 폴더 밖에서 git clone https://github.com/USERNAME/data-mse-plot.git을 실행한다. clone은 파일과 커밋 이력을 담은 새 로컬 저장소를 만들고, pull은 이미 가지고 있는 저장소의 현재 브랜치를 업데이트한다. 복제한 폴더에서 README대로 스크립트를 실행해 같은 그림을 재현한다.

6. 확인 문제와 다음 강의

  1. git add plot_data.py 직후 축 이름을 한 번 더 수정했다. 두 변경 중 어느 것이 다음 커밋에 들어가는지, 두 상태를 각각 어떤 명령으로 확인할 수 있는지 설명하시오.
  2. main에서 새 브랜치를 만들어 점 색을 바꾸시오. 그래프를 실행해 결과를 확인하고, 변경을 커밋한 뒤 GitHub에서 Pull Request를 열어 수정한 줄을 확인하시오.
  3. 저장소를 별도 폴더에 복제한 직후에는 plot.png가 없다. 그 이유와 그림을 재생성하는 방법을 설명하시오.

다음 강의에서는 측정점에 가장 잘 맞는 직선을 구한다. 적합 코드와 그림을 바꿀 때 측정점만 그린 상태와 적합선을 추가한 상태를 서로 다른 커밋으로 남겨 보자.
